- [+] сделано

**Новое:**
`String` в Haskell — это список символов. Для сети он не годится: медленно и много памяти.

### Этап 3 · Кодирование трёх символов

- [+] сделано

**Делаем:** `renderValue` и `decodeValue`.

HEOS кодирует **ровно три символа**:

| символ | код |
| -- | --- |
| `&` | `%26` |
| `=` | `%3D` |
| `%` | `%25` |

Больше ничего. Это **не** обычное кодирование URL: знак `+` остаётся плюсом, а не превращается в пробел.

**Ловушка:** при декодировании порядок замен важен. Если сначала заменить `%25` на `%`, а потом `%26` на `&`, то `%2526` расшифруется неправильно. Замену `%25` делай **последней**.

**Проверка:** `decodeValue (renderValue "a&b=c%d")` вернуло исходное.

### Этап 6 · Оболочка ответа

- [ ] сделано

**Делаем:** тип `Envelope` и разбор JSON в него.

Любой ответ усилителя выглядит так:

```json
{
  "heos":    { "command": "...", "result": "success", "message": "..." },
  "payload": ...,
  "options": [ ... ]
}
```

`payload` и `options` бывают не всегда.

**Новое:**
`aeson` — библиотека JSON. Чтобы тип умел читаться из JSON, нужен инстанс `FromJSON`. Самый простой способ — вывести автоматически:

```haskell
data HeosHeader = HeosHeader
  { command :: Text
  , result  :: Text
  , message :: Text
  } deriving stock (Show, Generic)
    deriving anyclass (FromJSON)
```

Если имена полей в JSON не совпадают с именами в Haskell — инстанс пишется руками:

```haskell
instance FromJSON Envelope where
  parseJSON = withObject "Envelope" $ \o -> do
    heos <- o .: "heos"
    payload <- o .:? "payload"     -- .:? для необязательных
    pure (Envelope heos payload)
```

Разбор: `eitherDecodeStrict :: ByteString -> Either String Envelope`.

**Проверка:** прогнать каждую фикстуру из `test/fixtures/`, все разобрались.

```haskell
import Network.Socket

resolve :: HostName -> IO AddrInfo
resolve name = do

  pure addr
```

### Этап 13 · Чтение в цикле

### Этап 14 · Потоки

- [ ] сделано

**Делаем:** запускаем чтение в отдельном потоке, а главный поток шлёт команды.

**Новое:**
`forkIO` запускает поток. Он дешёвый — их можно хоть тысячу.

Но у `forkIO` есть беда: если главный поток умрёт, дочерний останется висеть. И наоборот — если дочерний упадёт, никто не узнает.

Поэтому вместо него берём библиотеку `ki`:

```haskell
import Ki

Ki.scoped $ \scope -> do
  Ki.fork_ scope (readLoop sock "")
  -- здесь основная работа
  -- при выходе из scoped все порождённые потоки гарантированно убиты
```

Это называется структурная конкурентность: потоки не переживают блок, в котором созданы.

**Проверка:** программа читает события в фоне и одновременно принимает команды с клавиатуры.

### Этап 15 · Изменяемые ячейки

- [ ] сделано

**Делаем:** хранить последнее полученное событие в ячейке, которую видят оба потока.

**Новое:**

- `IORef` — обычная изменяемая ячейка. `newIORef`, `readIORef`, `writeIORef`.
- `TVar` — то же самое, но для транзакций. Работа с ним оборачивается в `atomically`.

```haskell
import Control.Concurrent.STM

v <- newTVarIO (0 :: Int)
atomically $ writeTVar v 42
x <- atomically $ readTVar v
```

Зачем `TVar`, если есть `IORef`: несколько изменений можно объединить в **одну** атомарную операцию. Либо всё случилось, либо ничего. Это называется STM — транзакционная память. Внутри `atomically` нельзя делать ввод-вывод, только работать с ячейками, и именно поэтому оно надёжно.

**Проверка:** один поток пишет, другой читает, значения не теряются.

### Этап 16 · Очередь событий

- [ ] сделано

**Делаем:** читающий поток кладёт события в очередь, а не печатает.

**Новое:**

- `TQueue` — очередь. `writeTQueue`, `readTQueue`. Чтение из пустой очереди **ждёт**, пока кто-нибудь не напишет.
- `TChan` + `dupTChan` — то же, но нескольким подписчикам сразу, каждый получит свою копию.

Для событий бери `TChan`: подписчиков может быть несколько.

**Проверка:** событие, положенное одним потоком, забирается другим.

### Этап 17 · Ждём ответа

- [ ] сделано

**Делаем:** послать команду и дождаться именно её ответа.

**Новое:**
`TMVar` — ячейка, которая может быть **пустой**. Чтение из пустой блокируется, пока туда не положат.

```haskell
box <- newEmptyTMVarIO       -- создали пустую
-- где-то в другом потоке:
atomically $ putTMVar box ответ
-- здесь:
ответ <- atomically $ takeTMVar box   -- ждём, пока положат
```

Это ровно то, что нужно: отправитель создаёт пустую коробочку и садится её ждать, читающий поток кладёт туда ответ.

**Проверка:** `getPlayers` возвращает результат, а не зависает.

### Этап 18 · Кто чего ждёт

- [ ] сделано

**Делаем:** карта «номер запроса → коробочка».

```haskell
TVar (Map Int (TMVar Response))
```

Порядок:

1. взять следующий номер
2. создать пустую коробочку, положить в карту под этим номером
3. послать команду с `SEQUENCE=<номер>`
4. ждать коробочку
5. **убрать из карты** — обязательно, при любом исходе

Читающий поток: пришёл ответ → вынул `SEQUENCE` из `message` → нашёл коробочку → положил → удалил из карты.

**Проверка:** послать три команды подряд, получить три правильных ответа, не перепутав.

### Этап 24 · Правильный запуск

- [ ] сделано

**Делаем:** последовательность при подключении, как велит производитель:

1. `system/register_for_change_events?enable=off` — выключить события
2. `system/sign_in` — войти (если в конфиге есть логин)
3. собрать состояние: `player/get_players`, `browse/get_music_sources`, `player/get_now_playing_media`, `player/get_volume`, `player/get_play_state`
4. `system/register_for_change_events?enable=on` — включить события

Почему такой порядок: если подписаться на события раньше, чем собрано состояние, засыплет уведомлениями, которые не к чему привязать.

**Ловушка:** CLI на аппарате «спит», пока никто не подключился. Сразу после подключения список плееров может быть неполным — подожди секунду.

**Проверка:** демон стартует и печатает полное состояние системы.

### Этап 35 · MCP-сервер

- [ ] сделано

**Делаем:** подключаем `mcp-server`, транспорт **HTTP** (не stdio — иначе демон будет перезапускаться на каждую сессию и вся идея пропадёт).

Инструменты. Чем меньше, тем лучше — агенту проще выбрать:

- `heos_status` — что играет, без аргументов, из кэша
- `heos_play_music` — найти и поставить: `query`, `kind`, `mode`
- `heos_transport` — `play` / `pause` / `next` / `prev`
- `heos_volume` — уровень, прибавить, приглушить
- `heos_search` — только найти, не ставить

Правила:

- аргументы плоские, без вложенности
- ответы короткие: агент платит токенами за каждый символ
- ошибки по-человечески: «усилитель не отвечает, возможно выключен», а не `ECONNREFUSED`

**Проверка:** инструменты видны, вызываются, музыка играет.

**Больше часа на одном месте** — скорее всего пытаешься сделать два дела сразу. Раздели.

**Непонятная ошибка компилятора** — смотри на **список эффектов** или на **тип**, который не совпал. Последняя строка сообщения cabal бесполезна, полезное выше.

**Тянет начать сначала и сделать красиво** — не надо. Красиво будет на третьем заходе, а сейчас нужно, чтобы играло.

**Скучно** — переходи к следующему этапу, вернёшься. Порядок важен только внутри части.
