## Наблюдения на живом аппарате

Прошивка 3.139.173, октябрь 2026. Всё ниже проверено руками, в спецификации этого нет или сказано иначе.

### SEQUENCE возвращается не всегда

Спецификация (2.1.3) обещает `SEQUENCE` только для `browse/*`. На деле аппарат копирует в `message` аргументы запроса, и `SEQUENCE` едет вместе с ними. Нет своих аргументов — нет и `SEQUENCE`.

| команда | отправили | `message` в ответе |
| -- | --- | --- |
| `player/get_players` | `SEQUENCE=1` | `""` — номер потерян |
| `system/register_for_change_events` | `enable=on&SEQUENCE=2` | `enable=on&SEQUENCE=2` |
| `player/volume_up` | `pid=…&step=1&SEQUENCE=0` | `pid=…&step=1&SEQUENCE=0` |
| `player/volume_down` | `pid=…&step=1&SEQUENCE=0` | `pid=…&step=1&SEQUENCE=0` |
| `player/set_play_state` | `pid=…&state=play&SEQUENCE=0` | `pid=…&state=play&SEQUENCE=0` |

**Вывод:** сопоставлять ответ с запросом только по `SEQUENCE` нельзя. Основной путь — одна команда в полёте на соединении команд и сверка по полю `command`; `SEQUENCE` — дополнительная проверка там, где он есть.

### События

- **Дубли.** На изменение громкости обычно приходят два одинаковых `event/player_volume_changed`, но бывает и одно (видели при `level=1`). На количество полагаться нельзя. Обработка событий должна быть идемпотентной: «записать значение», а не «прибавить».
- **Порядок после `play`:** ответ `set_play_state` → `player_now_playing_changed` (×2) → `player_state_changed` → `player_now_playing_progress`.
- **Прогресс шумит.** Пока играет музыка, `event/player_now_playing_progress` (`cur_pos`, `duration` в мс) приходит каждые 5 с. В логах — только на уровне debug.
- Во всех наблюдениях ответ на команду приходил раньше вызванных ею событий. Гарантии в спецификации нет — не полагаться.

### Поток и строки

- Каждое сообщение — одна строка JSON, конец `\r\n`. Пустых строк не встречалось.
- Короткий ответ (`get_players`, ~300 байт) приходит одним `recv`, но полагаться на это нельзя.

### Обнаружение

- SSDP с `ST: urn:schemas-denon-com:device:ACT-Denon:1` находит аппарат за один запрос; CLI слушает на порту 1255.
- `ST` по стандарту UPnP сравнивается точно: никаких кавычек вокруг URN. (Не проверено руками, как аппарат реагирует на неточный `ST`.)

### GHCi

- В GHCi `stdin` в режиме `NoBuffering`, и Backspace попадает в ввод как `^?`. Лечится `hSetBuffering stdin LineBuffering` в начале программы. В скомпилированной программе проблемы нет.

### Вывод из нескольких потоков

- `putStrLn` не атомарен: два потока, печатающие одновременно, перемешивают буквы (видели при остановке `printer` и `volumeTracker` по `q`: `volupmrei nttrearc:k esrt:o pspteodp`). В стенде терпимо. В демоне весь вывод идёт через логгер (этап 34), который пишет под одним замком. Временное лечение — `MVar ()` и `withMVar lock (\_ -> putStrLn …)` во всех местах печати.
